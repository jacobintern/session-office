# 專案小組：設計草稿（討論用）

狀態：定稿，2026-11-26。還沒實作。

## 目標

你開一個專案，只給目標和限制；組長負責拆工作、派工、收回報，你只看兩件事：
**專案卡在哪**，以及**要你決定的事**。

## 角色：能力完整，定位跟著工作走

- 每個 session 都是完整的 agent，不因角色少了能力。
- **組長**：一個專案一位。理解需求、拆工作、派工、彙整卡點和要你決定的事、控管人數。
- **成員**：組長派工時給定位，定位只對這件工作有效：
  - 實作：照範圍寫程式、跑單元測試。
  - 驗收：驗別人宣稱「做完了」的東西（跑測試、DEV 實測、找漏洞），不幫忙修，只回報。
  - 查證：查資料、讀程式、比對，給結論和證據。
- 同一個 session 這件是實作，下一件可以是驗收（但不能驗自己做的）。

## 硬規則（只有這幾條）

1. 做的人不驗收自己做的東西。
2. 組長不寫程式（它的 context 要留給全貌）。
3. 寫入動作照舊要你本人同意：開／關／合併 MR、push、轉 Jira 狀態、刪東西。組長彙整好問你，不能代你答應。
4. 每個專案最多 3 位成員（不含組長）；超過要問你。

## 流程

1. **開專案**：給目標、限制、資料夾（入口見「已定」）。橋接開一個 session 當組長，mod 依角色給它組長的規則。
2. **先跟你定計畫，再找人**：組長先拆工作、寫成任務清單（`tasks`）草稿，每件有編號、定位、範圍、完成條件，和你來回討論。
   **你核准計畫之前，組長不開任何成員、不派工。**核准之後照計畫找人；之後要加計畫外的工作、或人數超過上限，再問你。
3. **派工**：組長用派工單交給成員（現有 session 用 SendMessage，人不夠就開新 session）。派工單固定欄位：
   - 定位（實作／驗收／查證）
   - 範圍：做什麼、**不要碰什麼**
   - 完成條件：怎樣算做完
   - 交給誰：做完回報給組長，或直接交給某位驗收
4. **回報**：成員只回三種之一，貼到公佈欄並通知組長：
   - 完成（附證據：commit、測試結果、連結）
   - 卡住（卡在哪、需要誰）
   - 要決定（給組長彙整成你的「要你決定」）
5. **驗收**：實作回報完成 → 組長派另一位驗收 → 通過才算完成；不通過就把問題派回實作。
6. **你看到的**：專案總覽一列一個專案（卡在哪、等誰、幾件要你決定），手機和小視窗也看這份。

## 主動通知（先做的基礎）

有人貼卡或回報時，同專案閒著的 session 會被叫醒讀公佈欄，不用等它下一輪自己開始。

## 已定（11-26）

- **同一個 repo 同時只派一位實作，預設不用 clone**（11-26 實測後改）：Claude Code 的「信任這個資料夾」以 git repo 根目錄為單位，每個新 clone 第一次開都會停在信任提示，要你本人按。所以只有真的要兩人同時在同一個 repo 實作時才用 clone，組長要先在「要你決定」問你，並說哪個分頁會停在提示。
  clone 位置：repo 旁邊的 `.office-clones/<專案>/<repo>-<成員>`，origin 指回原 repo 的遠端。
  **單子結束要清掉**：組長收尾時先確認每個 clone 沒有未 push 的 commit、沒有未提交的改動，才移到 `~/.Trash`；有殘留就列出來問你。
- **任務清單是獨立的結構化資料**（`tasks`）：每件有編號、定位、負責人、狀態（待派／進行中／卡住／待驗收／完成）、卡住原因、更新時間；專案總覽從這份算出「卡在哪」。公佈欄留給自由文字的說明和進度。

- **入口只有一個「新開」按鈕**，表單上方切換兩種模式：
  - 單人：開一個不屬於任何專案的 session（之後仍可用 `/office project` 或桌卡上的 ✎ 指定話題）。
  - 專案：填目標、限制、資料夾、成員上限，開出來的就是組長。
  - **不能從表單把人直接加進專案**（11-26）：要加人就跟組長說，由組長用 `hire` 開，人數上限和成員規則只有這一條路。
- **組長預設 effort medium**，跟成員一樣；你覺得哪次拆得不好，就在頁面上把那位組長調成 high 重拆。不另外評估（怕燒用量），用了再觀察。
- **驗收不固定加 Codex 複審**：照全域規則，驗收的 session 在下「確認過」的結論前自己找 Codex 查證。
